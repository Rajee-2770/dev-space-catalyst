03 · Communication Method
WEBSOCKET

WebSocket — Persistent Two-Way Connection

Both client and server can send messages anytime — no need to ask first

API vs WEBSOCKET
API: Like sending letters — you write, wait, get reply
WebSocket: Like a phone call — both can talk anytime, connection stays open
Connection Flow
1. Client: “Upgrade to WebSocket?”
2. Server: “OK, upgraded!”
3. Now both send messages freely
4. Connection stays open until closed
REAL-WORLD USES
WhatsApp / Telegram Chat
Messages delivered instantly in real-time
Live Stock Prices / Crypto
Prices update every millisecond without refresh
Google Docs Collaboration
Multiple users typing — changes appear instantly
Online Gaming
Player positions, actions synced in real-time
Protocol: ws:// or wss:// (secured). Full-duplex — both ends talk simultaneously over a single TCP connection.

HOW IT WORKS

↓

↓

KEY PLAYERS

06 · Communication Method
SSE & POLLING

Server-Sent Events & Polling

Other ways to get updates from the server

Short Polling
Client asks server repeatedly at fixed intervals: “Any new data?” “Any new data?” “Any new data?”
e.g., Email inbox check every 30s
Wasteful — most requests return empty
Long Polling
Client asks, server holds the request open until it has data. Then responds & client immediately asks again.
e.g., Facebook chat (earlier versions)
Better, but still overhead from reconnections
SSE (Server-Sent Events)
Server opens a one-way stream and pushes events to client whenever ready. Client just listens.
e.g., Live sports scores, news feeds
Efficient — one connection, server pushes

07 · Real-World Scenario
ZOMATO / SWIGGY

How Does Zomato Track Your Order on Map Without Refreshing?

Your food is moving on the map in real-time — how?

The Complete Flow
1
Delivery partner's phone sends GPS coordinates every 3-5 seconds to the server via WebSocket or periodic API calls.
2
Server receives location, updates the order record in the database and pushes the new coordinates.
3
Your app is connected via WebSocket. Server pushes the new lat/lng to your device instantly.
4
Map SDK (Google Maps / Mapbox) smoothly animates the marker from old position to new position. No page refresh needed.
Technologies Used
WebSocket for real-time push
Google Maps SDK for map rendering
GPS/Location APIs on delivery phone
Redis for fast location caching
Also Used By
Uber/Ola — cab tracking
Dunzo — delivery tracking
Rapido — bike taxi tracking
Amazon — “delivery is 3 stops away”

08 · Real-World Scenario
SECURITY

Do Companies Actually Store Your Password?

Short answer: NO. Good companies never store your actual password. Here's why.

❌
The WRONG Way (Plain Text)
Database: | user | password | |----------|-------------| | raja | myP@ss123 | | john | secret456 | ⚠ If database leaks, ALL passwords are exposed!
✅
The RIGHT Way (Hashed)
Database: | user | password_hash | |----------|----------------------| | raja | a1b2c3d4e5f6... | | john | x9y8z7w6v5u4... | ✅ Even if DB leaks, attacker can't reverse the hash!
How Login Actually Works
1. You sign up → password is hashed → hash stored in DB (not the password)
2. You login → entered password is hashed again
3. Server compares hash vs stored hash — if they match, you're in!
4. That's why “Forgot Password” gives you a reset link, not your old password — because they don't have it!

09 · Security Concept
HASHING

Hashing — One-Way Transformation

Convert any input into a fixed-length string that CANNOT be reversed

HOW HASHING WORKS
Input: "hello"
↓ SHA-256
Output: 2cf24dba5fb0a30e...

Input: "Hello" (capital H)
↓ SHA-256
Output: 185f8db32271fe25...

Tiny change = completely different hash!
KEY PROPERTIES
One-Way
Cannot reverse hash back to original input
Deterministic
Same input always gives same hash
Fixed Length
SHA-256 always gives 256-bit output regardless of input size
Collision Resistant
Nearly impossible for two inputs to produce same hash
Algorithm
MD5
Broken — don't use for security
Algorithm
SHA-256
Secure — widely used
For Passwords
bcrypt
Slow by design — best for passwords
Used for: Password storage, file integrity checks (checksums), digital signatures, blockchain, data deduplication, Git commit IDs.

10 · Security Concept
SALT + HASH

Why Just Hashing Isn't Enough — Enter Salt

Attackers have precomputed hash tables (rainbow tables). Salt defeats them.

❌ Without Salt
User A: "password123" → hash: abc123 User B: "password123" → hash: abc123 Both have SAME hash! Attacker with rainbow table: abc123 → "password123" ⚠ CRACKED!
✅ With Salt
User A: "password123" + salt:"x7k2" → hash: qrs789 User B: "password123" + salt:"m3p9" → hash: tuv456 Different hashes! Rainbow tables are useless. Each user needs separate brute-force attack.
Salt = random string added to password before hashing. Stored alongside the hash. Makes each hash unique even for identical passwords. bcrypt automatically handles salting for you.

12 · Security Concept
ENCODING

Encoding — NOT Security, Just Format Conversion

Transforms data into a different format for transport/storage — easily reversible, no key needed

COMMON ENCODINGS
Base64
"Hello" → "SGVsbG8="
Used for: email attachments, embedding images in HTML, JWT tokens
URL Encoding
"hello world" → "hello%20world"
Used for: query parameters in URLs
UTF-8 / ASCII
Character → number mapping
Used for: text representation in all computers
KEY POINT
Encoding ≠ Encryption ≠ Hashing
Encoding: Anyone can decode. No key needed. Not for security.

Encryption: Need a key to decrypt. For confidentiality.

Hashing: Cannot be reversed at all. For integrity & password storage.
⚠ Common Mistake
Never use Base64 to “secure” passwords or secrets. It's not security — it's just a format change!

14 · Real-World Scenario
OAUTH

How Does “Sign in with Google” Work?

You click one button and you're logged in to a third-party app — but how?

1
You click “Sign in with Google” on an app (e.g. Spotify)
2
App redirects you to Google's login page (your password is never shared with the app)
3
You login to Google → Google gives the app an access token (a temporary pass)
4
App uses this token to fetch your name & email from Google — never your password
This is OAuth 2.0 — a protocol that lets apps access your info without ever knowing your password. The token expires, and you can revoke access anytime from Google Settings.

15 · Real-World Scenario
E2E ENCRYPTION

How Does WhatsApp End-to-End Encryption Work?

Even WhatsApp's servers can't read your messages

THE FLOW
1. When you install WhatsApp, your phone generates a key pair (public + private)
2. Public key is shared with WhatsApp server
3. Private key stays on YOUR phone only
4. When Alice sends a message to Bob:
  • Alice's phone encrypts with Bob's public key
  • Message travels encrypted through server
  • Only Bob's private key can decrypt it
WHAT THIS MEANS
❌ WhatsApp server cannot read your messages — it only sees encrypted gibberish

❌ Hackers intercepting the message get nothing useful

✅ Only sender & receiver can read the message

⚠ But: If someone has your unlocked phone, they can read messages (encryption protects the transit, not the device)
Uses: Signal Protocol (also used by Signal app). This is Asymmetric Encryption in action — public key encrypts, private key decrypts.
