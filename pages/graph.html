Graphs

A Graph is a collection of nodes (people, cities, pages) connected by edges (friendships, roads, links).

You interact with graphs every single day — often without knowing it.

🗺Google Maps — cities are nodes, roads are weighted edges. Shortest path = Dijkstra.
👥Instagram / LinkedIn — you are a node. Every follow/friend is an edge.
🌐Google Search — every webpage is a node, every hyperlink is a directed edge.
📦npm / Maven — packages are nodes, dependencies are directed edges (DAG).

Quick Question
🤔 THINK FIRST

Is A→B and B→A a cycle?

The answer depends on whether the graph is directed or undirected

Undirected Graph
A—B is one edge traversed in both directions.
Going A→B→A just backtracks on the same edge — this is NOT a cycle.
A simple cycle needs at least 3 nodes (e.g. A→B→C→A).
❌ NOT a cycle
Directed Graph
A→B and B→A are two separate directed edges.
You can travel A→B→A→B→... forever — this IS a cycle.
Directed cycles can involve just 2 nodes.
✅ YES — a 2-node directed cycle
Key insight: In a directed graph, detecting cycles matters a lot — circular dependencies in npm, deadlocks in OS, and infinite redirects in web servers are all directed cycles. Detection uses DFS + tracking nodes currently on the recursion stack.

🗺️ GPS & NAVIGATION

Shortest Path — Dijkstra's Algorithm

Road networks are weighted graphs · cities = nodes · roads = weighted edges

Graph type: Weighted undirected graph — each edge has a cost (distance / travel time)
Problem: Find the minimum-cost path from Start (A) to End (E) through any combination of roads
Algorithm — Dijkstra's: Greedily picks the nearest unvisited node, then relaxes outgoing edges: if dist[u]+w < dist[v], update dist[v]. Time: O((V+E) log V)
Result: A → B → D → E costs 30 — cheaper than the direct road A→B→E (35) or any other route

Degrees of Separation — BFS from Alice

Users = nodes · friendships = edges · "Six degrees of separation" is a BFS problem

Graph type: Undirected graph — friendships are bidirectional (mutual follow or friend request)
Problem: Given two users, find the shortest connection path between them — "how many mutual friends apart are they?"
Algorithm — BFS: Run BFS from source user. Level 1 = direct friends. Level 2 = friends-of-friends. The level at which target is found = degree of separation
At scale: Facebook found the average separation is 3.57 hops among 1.5B users. LinkedIn shows "2nd" and "3rd" degree connections using this exact BFS result

📦 PACKAGE DEPENDENCIES

npm Install — Topological Sort on a DAG

Packages = nodes · "depends on" = directed edges · A DAG ensures no circular deps

Graph type: DAG (Directed Acyclic Graph) — directed edges mean "A needs B", and there are no cycles (npm would error on circular deps)
Problem: Install packages in the correct order — a package must be installed AFTER all its dependencies are ready
Algorithm — Kahn's Topological Sort: Find all nodes with in-degree=0 (no prerequisites), install them, remove their edges, repeat. O(V+E)
Why a graph? Any package manager (npm, pip, Maven, apt) uses this internally. Circular dependencies are detected by checking for cycles in the DAG

🗂️ FILE SYSTEM

Directory Tree — DFS Traversal

Directories = nodes · parent/child relationships = edges · A tree is a special graph

Graph type: Rooted tree (special case of a graph) — each node has exactly one parent, except the root (/)
Problem: Traverse every file and directory (e.g. for search, backup, permissions check). Visit each node exactly once
Algorithm — DFS: Dive as deep as possible before backtracking. Natural for trees. Recursive implementation mirrors the call stack. O(V) for a tree with V nodes
Real impact: find, grep -r, IDE project scanning, antivirus, git status — all use DFS to walk the directory tree. Symlinks can turn the tree into a DAG

Traversals · Comparison

BFS vs DFS — Understanding the Difference

Same graph, same start. BFS fans outward in waves · DFS dives deep first. The exploration ORDER is completely different.

BFS — Breadth First (Queue)
Spreads level by level · numbers = visit order
Visit order: A → B → C → D → E → F → G
Visits all of level 1 before going to level 2. Each level is complete before the next starts.
DFS — Depth First (Stack)
Dives deep left branch first · numbers = visit order
Visit order: A → B → D → E → C → F → G
Goes all the way down the left branch (A→B→D, then E), then backtracks to visit C and its children.
💡 Same tree, same start node (A). Notice C is ③ in BFS but ⑤ in DFS. BFS reaches the right subtree before finishing the left. DFS exhausts the entire left branch first, then backtracks to the right.
Full Comparison

Data structureQueue (FIFO)Stack (LIFO) or recursion

Shortest path✅ Always (unweighted)❌ Not guaranteed
Space (worst)O(V) — wide frontierO(V) — deep call stack

Use BFS for...
Shortest Path — Maze, Word Ladder, Bipartite check

Rule of thumb: If the problem asks for shortest path or minimum steps → BFS. If it asks for all paths, cycles, ordering, or backtracking → DFS. When in doubt, both are O(V+E) — pick based on what the problem needs.

Interview Question 1 of 10
Q1 · Easy

What is the difference between BFS and DFS? When would you use each?

ANSWER
+
BFS uses a Queue, explores level-by-level, guarantees shortest path in unweighted graphs. DFS uses a Stack/recursion, explores depth-first, natural for backtracking.

Use BFS for: shortest path, level-order, nearest neighbor. Use DFS for: cycle detection, topological sort, maze solving, connected components.

Interview Question 2 of 10
Q2 · Easy

What is an Adjacency List vs Adjacency Matrix? Which is better?

ANSWER
+
Adjacency Matrix: 2D array, O(1) edge lookup, O(V²) space — good for dense graphs.
Adjacency List: Array of lists, O(V+E) space, O(degree) neighbor iteration — better for sparse graphs (most real-world ones).

In interviews, adjacency list is the default choice. Use matrix when you need constant-time edge queries.

Interview Question 3 of 10
Q3 · Medium

How do you detect a cycle in a directed graph?

ANSWER
+
Use DFS with a recursion stack (not just a visited array):
1. Maintain two arrays: visited[] and recStack[]
2. During DFS, add node to recStack when entering, remove when leaving
3. If you encounter a node already in recStack → cycle found!

Why recStack? visited[] alone misses back edges in directed graphs. recStack tracks the current DFS path. Time: O(V+E).
↓
Interview Question 4 of 10
Q4 · Medium

What is Topological Sorting and when is it used?

ANSWER
+
A linear ordering of vertices in a DAG such that for every directed edge u→v, u comes before v.

Algorithms:
• Kahn's (BFS-based): Use in-degree. Repeatedly pick nodes with in-degree 0, remove them and decrement neighbors.
• DFS-based: Run DFS; push to stack after all neighbors visited. Pop order = topological order.

Use cases: npm/Maven dependency resolution, course prerequisites, build systems, task scheduling.

Interview Question 5 of 10
Q5 · Medium

How do you find the number of connected components in an undirected graph?

ANSWER
+
Iterate over all unvisited vertices; start a BFS/DFS from each unvisited one, incrementing a counter each time.

count = 0
for v in 0..V-1:
  if not visited[v]:
    bfs/dfs(v)
    count++

Alternatively use Union-Find (Disjoint Set Union) — union edges together, count distinct roots. O(V+E) either way.

Interview Question 6 of 10
Q6 · Medium

What is Dijkstra's algorithm and when does it fail?

ANSWER
+
Dijkstra finds the shortest path from a source to all vertices in a weighted, non-negative graph.

Uses a min-heap (priority queue): always relaxes the closest unvisited vertex. Time: O((V+E) log V).

It FAILS when: edges have negative weights (use Bellman-Ford instead, O(VE)). A single negative edge can make Dijkstra return wrong answers because it assumes adding an edge can only increase cost.

Interview Question 7 of 10
Q7 · Medium

How do you check if a graph is bipartite?

ANSWER
+
A graph is bipartite if its vertices can be 2-colored (say RED/BLUE) such that no two adjacent vertices share the same color. This is equivalent to: the graph has no odd-length cycle.

Algorithm (BFS 2-coloring):
1. Start BFS, color source RED
2. Color every neighbor the opposite color
3. If you ever find a neighbor with the same color as current → NOT bipartite

Time: O(V+E). Works on disconnected graphs too (run for every component).

Interview Question 9 of 10
Q9 · Hard

Given a grid of 0s and 1s, find the number of islands. (LeetCode 200)

ANSWER
+
Classic DFS/BFS on a 2D grid. Treat each cell as a graph node; edges connect to 4 neighbors (up/down/left/right).

Algorithm:
1. Iterate over every cell in the grid
2. If cell = '1' and unvisited → start DFS, mark all connected '1' cells as visited, increment count
3. Return count

Time: O(M×N). Space: O(M×N) call stack. Can also use Union-Find for O(α(MN)) effectively O(1) per union.
↓
Interview Question 10 of 10
Q10 · Hard

How would you find the shortest path between two users in a social network with billions of users?

ANSWER
+
Bidirectional BFS — start BFS simultaneously from both source and target. When the two frontiers meet, you've found the shortest path. Reduces search space from O(b^d) to O(b^(d/2)).

For billions of users:
• Partition the graph across machines (graph sharding)
• Use distributed BFS with message passing
• Cache friend-of-friend edges (LinkedIn does this)
• Accept approximate answers (e.g. within 6 degrees)

Facebook's "Six Degrees" uses this approach — most users are within 3.57 hops of each other.
