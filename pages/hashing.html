02 · Real World

How Hashing is Used in Real-Time

Hashing is everywhere — you use it dozens of times a day
🔐
Password Storage
Your password is never stored raw. bcrypt/SHA-256 converts it to a hash. On login, input is hashed and compared — the original is never recovered.
"MyPass123" → $2b$12$k8v...aX9
⚡
Caching (Redis, CDN)
Cache keys are hashed to route requests to the right node. Consistent hashing distributes keys across multiple servers with minimal reshuffling.
hash("user:42:profile") → node-3
📁
File Integrity (Checksum)
When you download a file, SHA-256 hash verifies nothing changed. Git uses SHA to identify commits — a tiny edit creates a completely different hash.
git log: a3f9c2d... → unique commit
🌐
Load Balancing / Routing
Hash of user IP/session ID consistently routes the same user to the same backend server, enabling sticky sessions without shared state.
server = hash(ip) % num_servers
🔍
Deduplication
Dropbox hashes file blocks — if the block hash already exists in cloud, it skips upload. Saves bandwidth. Same for email spam dedup.
seen.contains(hash(block))? skip
🧬
Blockchain / Crypto
Each Bitcoin block contains the hash of the previous block — changing any block invalidates all later hashes. SHA-256 is the backbone of Bitcoin mining.
block_hash = SHA256(prev + data)

Q1 of 10 · FUNDAMENTALS
Easy
What is a hash function and what properties must a good hash function have?
HINT
Think about determinism, speed, and distribution of output across the index space.
ANSWER
A hash function maps a key of arbitrary size to a fixed-size integer (the hash code), which is then mapped to a bucket index via index = hash(key) % capacity.

Properties of a good hash function:
1. Deterministic — same key always produces same hash
2. Fast — should run in O(1)
3. Uniform distribution — minimizes collisions, spreads keys evenly
4. Avalanche effect — small input change → large output change
5. Low collision rate — different keys should rarely hash to the same slot
"hello" → 2cf24dba…
"hellp" (+1 char) → a5c4a4af…

Q2 of 10 · INTERNALS
Easy
What is a collision in a hash table? Explain the two main ways to resolve it.
HINT
Two keys map to the same bucket index. One solution stores extra nodes; the other probes for a new slot.
ANSWER
A collision occurs when two different keys hash to the same bucket index.

1. Separate Chaining — each bucket holds a linked list (or tree). Colliding entries are appended to the chain. Java HashMap uses this; chains become Red-Black Trees when they exceed 8 nodes.

2. Open Addressing — on collision, probe for the next empty slot in the array.
  • Linear probing: +1, +2, +3…
  • Quadratic probing: +1², +2²…
  • Double hashing: uses a second hash function

Open addressing uses less memory but suffers from clustering; chaining handles high load factors better.
↓
Q3 of 10 · COMPLEXITY
Medium
Why is HashMap O(1) average but O(n) worst case? When does worst case happen?
HINT
Think about what happens when all keys hash to the same bucket.
ANSWER
Average O(1): With a good hash function and a low load factor, each bucket has ~1 entry. get/put inspects only that bucket → constant time.

Worst O(n): If all n keys collide to the same bucket, the lookup must traverse the entire chain of length n → O(n).

This can happen due to:
• A poor hash function with few distinct outputs
• A malicious adversary crafting keys with the same hash (HashDoS attack)

Java 8+ mitigates this: when a bucket chain grows past 8 nodes, it converts to a Red-Black Tree, making worst case O(log n) per bucket, not O(n).
↓
Q4 of 10 · CONTRACT
Medium
If two objects are equal (equals() returns true), must their hashCode() be the same? What about the reverse?
HINT
This is the Java hashCode/equals contract. One direction is mandatory; the other is ideal but not required.
ANSWER
Rule 1 (mandatory): If a.equals(b) == true, then a.hashCode() == b.hashCode() MUST hold. Violating this breaks HashMap — the map will fail to find an existing key.

Rule 2 (not required): If a.hashCode() == b.hashCode(), it does NOT mean a.equals(b). This is just a collision — two different objects can share a hash code.

Mnemonic: Equal objects → same hash. Same hash ≠ equal objects.

Common mistake: Overriding equals() without overriding hashCode() — this silently breaks any HashMap/HashSet usage of that class.
↓
Q5 of 10 · DESIGN
Medium
What is the load factor and why does Java use 0.75 as the default? What happens during rehashing?
HINT
Load factor = entries / buckets. Think about the space-time tradeoff at different load values.
ANSWER
Load factor λ = n / capacity

Why 0.75? It's a sweet spot from Poisson distribution analysis:
• λ < 0.5 → too many empty buckets → wasted memory
• λ > 0.9 → too many collisions → O(n) lookups
• λ = 0.75 → roughly 0.5 expected probes per lookup, good space-time balance

Rehashing process:
1. A new array of 2× capacity is created
2. Every existing entry is re-inserted using the new capacity (new index = hash & (newCap-1))
3. Old array is discarded
Cost: O(n) one time, amortized O(1) per insert.

Q6 of 10 · SECURITY
Medium
Why should you never use MD5 or SHA-1 for password storage? What should you use instead?
HINT
Think about speed — fast is bad for passwords. Also think about rainbow tables.
ANSWER
Problems with MD5/SHA-1/SHA-256 for passwords:
1. Too fast — a GPU can compute billions of SHA-256 hashes/sec, enabling brute-force attacks
2. No salt by default — same password always gives same hash; rainbow tables precompute common hashes
3. MD5/SHA-1 are cryptographically broken — collisions can be engineered

Use instead:
• bcrypt — deliberately slow, built-in salt, work factor configurable
• Argon2 — winner of Password Hashing Competition 2015; memory-hard, parallelism-resistant
• scrypt — memory-hard, used in Litecoin

Rule: For password hashing, slow is good. For data integrity, fast is good.

Q7 of 10 · ALGORITHM
Hard
Solve "Two Sum" using a HashMap. What is the time and space complexity?
HINT
For each number, check if (target - number) already exists in the map.
ANSWER
// Two Sum — O(n) time, O(n) space int[] twoSum(int[] nums, int target) { Map<Integer, Integer> map = new HashMap<>(); for (int i = 0; i < nums.length; i++) { int complement = target - nums[i]; if (map.containsKey(complement)) { // O(1) lookup return new int[]{map.get(complement), i}; } map.put(nums[i], i); // O(1) insert } return new int[]{}; } // Example: nums=[2,7,11,15], target=9 // i=0: complement=7, not in map → put(2,0) // i=1: complement=2, found at 0 → return [0,1] ✓
Time: O(n) — single pass, O(1) HashMap operations
Space: O(n) — map holds at most n entries
vs Brute Force: O(n²) time, O(1) space — HashMap trades space for time.

Q8 of 10 · DESIGN
Hard
What is consistent hashing? Why is it used in distributed systems like Redis Cluster and CDNs?
HINT
Think about what happens when you add or remove a server from a cluster using regular modulo hashing.
ANSWER
Problem with regular hashing: server = hash(key) % n. When you add/remove a server, n changes → almost every key remaps to a different server → massive cache miss storm.

Consistent Hashing solution:
1. Map servers and keys to a circular ring (0…2³²)
2. A key is assigned to the first server clockwise on the ring
3. Adding/removing a server only remaps ~k/n keys (k=keys, n=servers) — minimal disruption

Virtual nodes (vnodes): each real server gets multiple positions on the ring for better load balance.

Used in: Redis Cluster, Amazon DynamoDB, Apache Cassandra, CDN routing, Memcached.

Q9 of 10 · DATA STRUCTURE
Hard
What is a Bloom Filter? How does it use hashing? What are false positives and false negatives?
HINT
A Bloom filter uses a bit array and multiple hash functions. Think about what "might exist" vs "definitely not exist" means.
ANSWER
A Bloom Filter is a probabilistic data structure using a bit array + k hash functions for space-efficient membership testing.

Insert(x): compute h₁(x), h₂(x), h₃(x) → set those bits to 1
Contains(x): if ALL k bits are 1 → "possibly yes"; if ANY bit is 0 → "definitely no"

False Positive: "possibly yes" but element was never inserted (bits set by other elements). Tunable with more bits/hash functions.
False Negative: impossible — if element was inserted, its bits are set forever.

Used in: Google BigTable (avoid disk reads for missing keys), Chrome malware URL filter, Cassandra, Redis, spell checkers, CDN cache miss reduction.

Q10 of 10 · ALGORITHM
Hard
Design an LRU Cache with O(1) get and O(1) put. Which data structures do you use and why?
HINT
You need O(1) access AND O(1) order update. Hint: one structure for lookup, another for ordering.
ANSWER
Combine a HashMap (O(1) key→node lookup) with a Doubly Linked List (O(1) add/remove from front/back, maintains recency order).
class LRUCache { int capacity; Map<Integer, Node> map = new HashMap<>(); DoublyLinkedList list = new DoublyLinkedList(); int get(int key) { if (!map.containsKey(key)) return -1; Node node = map.get(key); list.moveToFront(node); // O(1) — most recently used return node.val; } void put(int key, int val) { if (map.containsKey(key)) { map.get(key).val = val; list.moveToFront(map.get(key)); } else { if (map.size() == capacity) map.remove(list.removeTail().key); // evict LRU Node node = new Node(key, val); list.addToFront(node); map.put(key, node); } } }
get: O(1) HashMap lookup + O(1) list move
put: O(1) insert + O(1) evict tail
Used in: OS page replacement, browser history, CPU cache, Redis TTL eviction.
